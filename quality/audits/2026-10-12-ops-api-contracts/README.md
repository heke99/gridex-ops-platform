# Gridex OPS API audit and proposed corrections

The audit uses actual OPS handlers, their callees, and the connected PostgreSQL catalog as authority. Tests verify local changes and are not evidence that the deployed APIs or database are correct. Gridex Web is outside scope. No business RPC, live customer mutation, provider request, email, native capture, job replay or deployment was performed. One explicitly authorized OPS forward DDL migration has now been applied and checked against actual metadata; see `atomic-native-apply-receipt.json`.

The public families have method/path and dependency inventories in `website-review.json`, `customer-review.json`, `staff-review.json`, `partner-review.json` and `documentation-review.json`. `internal-review.json` additionally records actual authorization/tenant/cron/provider boundary inspection of all 154 methods across 129 routes, with deeper business/native limits listed explicitly. `database-code-review.json` records the full 758-function catalog, relation/ACL/RLS/constraint/trigger evidence and effective source comparisons. Counts overlap where APIs share endpoints and publication routes; they are not an all-green score.

Confirmed application corrections include credential/company authorization, customer identity binding and assertion issuance checks, truthful nullable public DTOs, canonical published-offer direction checks, complete paged measurements, site-bound idempotent POA replay, diagnostic/legal/portfolio serialization, server-issued Staff download trace IDs, read-only provider diagnostics, and invoice dispute/event receipt concurrency guards. The root consolidation record and family reports distinguish corrected source from unchanged live behavior.

Documentation `2026-10-12.1` is prospective. The default Website/Customer/Staff response schema remains `2026-10-09.1`; onboarding remains independently `2026-10-05.2`, and the minimum is unchanged. Supported optional credential pins are selected by server-owned metadata, never caller version headers. Frozen earlier releases remain byte-identical. Two historical strict-schema contradictions are explicitly recorded in the compatibility policy; response field projection cannot manufacture missing market evidence or satisfy an impossible closed support-detail schema.

The fresh read-only preflight confirms 51 missing required functions: five public customer/document retention guards plus 46 internal command functions, mapped to 74 valid-command method chains. Forward migration `20261012235455` has installed the latest deny-aware actor permission gate, additive canonical permission-override columns and constraints, and the atomic Partner site/offer direction guard. Exact applied SQL matches its new source file; function identities, ownership and existing ACLs were preserved. The pure grid-owner normalizer remains unchanged in native SQL; the new forward source corrects its historical replay escaping. The tombstone-list function is present; an earlier prose classification error was corrected against the original and fresh catalog evidence. These are release blockers, not automatically 51 failed live requests. No existing exploitation or corrupt contracts were observed or claimed.

See `release-proposals/README.md` for the applied atomic correction and remaining additive reconciliation inputs. This work does not certify authenticated live Staff/customer readiness, provider delivery, or the full Ediel campaign. The separate campaign's claims, frozen acceptance register, shared memory and canonical captures are unchanged.

The final serialization review also confirmed that a nonempty public event list was rejected by the generic internal-ID guard. The correction accepts only the mapper's existing opaque `event_` plus 32 lowercase hexadecimal reference at `data[n].event_id`, preserving the published field and all other ID restrictions.
