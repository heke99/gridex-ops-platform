## Confirmed ancillary gap

**P3 — onboarding response request ID is not supplied to request logging.** `identityResolution.ts` and `onboarding.ts` generate the response UUID only inside `json()` after invoking `logRequest`, and none of their log calls passes `requestId`. `logIntegrationApiRequest` consequently persists the inbound `x-request-id` (or null), while callers receive a different generated response ID. This does not bypass identity, tenant isolation or canonical effects and does not block frontend construction. It limits troubleshooting of failed/successful onboarding. Narrow fix: allocate one ID at handler entry, reuse it in every response and pass it explicitly to every log call; retain any validated client correlation separately. Normal Staff already implements this correctly. Proof is direct source data flow; no runtime reproduction was authorized. The normal Staff guide's request/log ID guarantee should not be assumed to cover these separate onboarding handlers until corrected.
