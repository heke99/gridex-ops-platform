## Transaction, concurrency and recovery boundary

The actual clean runner makes separate psql calls without single-transaction.
I/F/D/6D2 have **no top-level BEGIN/COMMIT**: ordinary statements commit separately,
DO blocks are atomic individually, and called functions use their caller's unit.
The actual prefix has explicit BEGIN/COMMIT in entries27,28,29 and33. Entry33 uses
ACCESS EXCLUSIVE invitations lock with local5s lock/30s statement timeouts and
commits, releasing that lock before I. Its local timeouts do not carry into the
next psql session. A wrapper around the complete prefix cannot promise rollback
across embedded commits.

For isolated tests, set finite session lock/statement timeouts independently for
every source psql invocation (e.g.5s/30s for focused contention, a documented larger
finite statement budget for full-source execution). Assert actual timeout settings.
No failure code from a fabricated exception counts as contention evidence.

Required failure receipts:

- I: fail ownership DO with a synthetic missing join column; preceding FK DO has
  committed, failing ownership DO rolls back. Source stops before import CREATE.
- F: duplicate nonnull token UUID values with company_invitations_token_key
  absent cause native23505 at F65 before later backfills/seeds. A wrong same-name
  index is a pre-mutation admission rejection; separate reduced characterization
  records the source IF NOT EXISTS skip, not a native failure. A separate
  late helper/policy or final customer-filter missing-column failure preserves
  prior committed defaults, seed and policy units. Individual bespoke policy
  DROP/CREATE pairs can leave a named policy absent.
- D: invalid status/confidence makes ADD fail after the preceding DROP has
  committed; raw failure leaves the old check absent. FK DO rollback does not
  roll back alignment ADDs; late view replacement failure retains earlier units.
- 6D2: invalid user-role status aborts its first shared lifecycle DO including its
  UPDATE. Late missing overview column fails the final DO but retains earlier
  lifecycle effects, journal, helpers, policies, triggers and completion columns.
- For every case inspect exact source statement/SQLSTATE (42703,23505,23503,
  23514 or23502 only when that native operation actually produces it), failing-
  unit rollback and prior-unit committed deltas. Dirty admission diagnostics
  remain distinct from deliberately bypassed admission in disposable native-
  failure characterization. Reset from a clean known template and rerun; do not
  blindly retry an unknown partial state or silently repair it.
- Hold a conflicting lock in another disposable connection, enforce finite timeout,
  observe55P03 and lock release/committed prefix. Let a writer change a valid
  prerequisite after Task7's checker finishes; fresh admission must reject the
  altered state. The old snapshot is deliberately insufficient evidence.

**Concurrent existing-row application is excluded from the next implementation.**
Synthetic existing-row compatibility is not a production executor. A future
existing-data application contract must implement and prove this sequence:

1. Enforce a fence covering application reads/writes, worker/queue/webhook traffic,
   direct database sessions, DDL, function/default/trigger/policy/role/ACL changes
   and all referenced parent tables/auth identities. Drain prior transactions and
   verify the drain. A voluntarily observed app flag/advisory lock is insufficient.
2. Only after drain, run fresh Task7 plus the6D2 admission contract against the
   exact fenced database/source revision. Snapshot IDs/values/catalog and enumerate
   explicitly approved source deltas, including F seed metadata/grants and6D2
   UPDATE-trigger effects. Reject preservation violations before invocation.
3. Revalidate immediately before each source, with stage-aware expectations: I-
   created relations are present before F; F effects before D; full imports before
   6D2. Retain exclusivity across every autocommitted statement and all downstream
   postflight, not just the initial checker. Include relation identity/signatures,
   dependency values and newly enabled policy/trigger effects in the checks.
4. Keep traffic closed on SQL failure, unexpected delta, connection loss or missing
   completion receipt. Recover only under a reviewed plan from known committed
   boundaries/backup with fresh admission; no automatic retry or reopened traffic.
   Reopen only after complete postflight and final reviewed access/retention gates.

A separate session holding conflicting table locks would also block this source
executor, so it is not a fence implementation. A genuinely atomic alternative
**after prefix33** requires a separately reviewed single executor transaction,
locks acquired by that executor in deterministic dependency order, exclusion of
concurrent DDL/role/ACL changes, admission repeated after locks, and proven timeout,
rollback and postflight behavior. It can wrap these four originals because they
lack embedded commits, but cannot roll back prefix33. No such runner/fence is
implemented or claimed by this contract.
