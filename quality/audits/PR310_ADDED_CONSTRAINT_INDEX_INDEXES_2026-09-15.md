## AI-001 — expired unreleased AGT lock (P2), caller corrected

`ediel_test_run_locks_one_active_agt_uidx` is exactly:

```sql
CREATE UNIQUE INDEX ediel_test_run_locks_one_active_agt_uidx
ON public.ediel_test_run_locks USING btree
(company_id, actor_role, message_family, environment_type)
WHERE (released_at IS NULL)
```

The June2 source deliberately retains one unreleased lock per complete transport
scope. Before correction, `acquireAgtRunLock` filtered existing locks by a future
expires_at, then attempted to insert a new lock when an expired unreleased row
was present. That existing row still satisfied the unique predicate, so the
new insert conflicted. Expiration alone never released the database lock.

The root agent corrected the caller to check every unreleased lock, preserve
all four scope filters, and report a concurrent 23505 acquisition as busy.
Other database errors still propagate. Both messages now point to the explicit
“Släpp lås” action in Test Center. That platform-admin action writes released_at
(`app/admin/ediel/test-center/actions.ts:294–313`), and the actual button is at
`page.tsx:242–245`. No implicit release-on-expiry or release-on-failure behavior
is invented. The unique index remains unchanged.
