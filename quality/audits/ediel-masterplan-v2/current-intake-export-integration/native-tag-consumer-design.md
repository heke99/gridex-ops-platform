## Minimal proposed seam and allocation

**OPS03 owner:** expose one read-only function from its existing runner, provisionally `readVerifiedIndividualCaseResults({ repository, candidateSha, candidateTree, qualificationRefs, github })`. `qualificationRefs` point to existing immutable native-owner packets; they select evidence and cannot grant qualification. `github` is the existing authenticated read/download transport or a declared finite test port. Import must not execute the runner's CLI: the owner supplies the normal `require.main === module` guard around existing orchestration, preserving CLI behavior. No new command runner, manifest, emitted proof or producer is necessary.

Return only reader-derived `{ files, blockers }`, where each file contains normalized repository path, exact executed file hash, selected case names and their actual outcomes, source execution mode, and verified run/attempt/job/artifact/archive/JUnit identities. A file is `passed` only when its reviewed required case selection is present, uniquely identified and passing with the expected execution/source scope. Missing/unselected/error/skipped cases stay distinct; arbitrary declared `passed`, `native`, `sourceQualified`, global count or label fields are never authoritative. Successful relevant cases do not make the whole rule matrix complete.

**Scanner root:** add native discovery separately from unit TS invocation, and call that function once for existing qualified evidence. Never send discovered native files to default unit Vitest. Join actual file/case/source results to tags; an absent native result must not fall through to the current "not in failedFiles therefore green" assumption. Keep unqualified native discovery visible as unverified; `--check` must reject an approved native-dependent row without qualified required execution. Preserve existing unit/CJS execution and approval-edit behavior. Do not add dummy wrappers or use a green sibling job to supply a missing file.

**Native owners, including DB04/05:** supply exact repository, immutable producer/workflow head and tree, run ID/attempt, job ID/name, artifact ID/digest/member paths, raw JUnit case names/counts, selected test/config/source/migration/replay hashes and full expected/prohibited effect mapping in their existing packets. DB04 also retains its current real-callsite/selective-sample review requirements; accounting does not cure that whole-card gap. DB05 retains separate schema/source admission and retention-class effects. No existing artifact is reset or newly emitted for this interface.

**Source/capture coordinator:** qualify source compatibility when a previously executed source differs from the consumer candidate. Exact file hash alone is insufficient for changed transitive SQL/helper/permission/runtime scope. Default to same reviewed source; reuse historical source only through the existing authenticated source-qualified carry boundary. In particular, BASE-plus-forward native receipts remain that execution mode and cannot be renamed candidate clean/upgrade/capture proof.

## Custody requirements to reuse, not reimplement

The owner reader must authenticate actual run/attempt/head/tree, completed job and its real result, artifact's association/digest, safe unique ZIP members/CRC, raw JUnit and exact file/case identities, and executed-input hashes/selector/source mode. It must compare these against immutable reviewed source and expected case bindings, rather than trust the artifact's own labels. Existing selected source/effect review establishes fixture/ports, tenant/DDQ/DGI/cross-assignment scope; JUnit names alone cannot establish those semantics. Reject runner-step JUnit as individual-native case evidence. Reader outputs keep document/unit/integration/tenant-E2E/transport/TGT levels separate and cannot grant formal market approval.

The scanner's ordinary job may run before native evidence exists. This must remain pending/unverified, not green. The existing CI owner must decide whether its coverage consumer reads an already completed current-source artifact or waits through an existing job dependency/channel; changing workflow dependencies needs explicit file allocation to that owner. Do not add a native execution or duplicate coverage producer to solve timing.

## Necessary finite negative controls

OPS03's existing consumer test should exercise genuine fixtures for: wrong repo/head/tree/run attempt/job/artifact association; wrong ZIP/JUnit digest; unsafe, duplicate or malformed artifact members; global green with absent selected case; foreign same-named file/case; duplicate case identities; fail/error/skip/unselected selected cases; orchestrator-step XML; changed test/helper/SQL/config/source hashes; forged qualification/level flags; stale selector/count; and BASE-overlay execution mislabeled as canonical candidate. One positive exact native case set must be accepted through the existing reader and retain scope/ports. Current-head failures may not be replaced with a successful older attempt.

Scanner controls need only prove that a discovered native file is not spawned by unit Vitest, a qualified reader result maps to its real tag, missing/failed/unqualified results do not become green, unknown IDs still fail, and existing unit/CJS handling remains intact. These are consumer contract tests with finite read ports, not new native proof or whole-card tests.
