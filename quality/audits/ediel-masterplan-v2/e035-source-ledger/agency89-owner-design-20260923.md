## Source requirement (under 200 words)

Frozen P26.A r3 SHA256 `83c2f1d2915851d2e670731f6ab404ef06c9b9def282afbafdfa0eda836a6e95`, actual text `sources/prodat.txt`: p47 LIN/C212 field209 permits at most25 characters and agency3055=89 for distributor-assigned identities or9 for GS1. Its examples include multiple89 objects and repeated registers. P114/116 distinguish physical objects and preserve the same object ID across their registers. P120 requires agency to agree with identity. These establish nationally applicable89 support; they do not supply a particular legacy-record correspondence. The issuer component proposed below is an engineering consequence of distributor assignment. Exact decoded identifier, agency and assigning network owner must survive parsing and binding; uppercasing, punctuation removal or relabelling89 as9 is not qualification.

## Recommendation and smallest coherent boundary

Add a typed, immutable, source-owned identity-to-point binding, initially produced by a genuinely correlated Z02 facility response. Carry that binding through the actual Z04 supply commitment and later reviewed structures into the existing UTILTS comparison. An alias-table-only patch, an agency allowlist expansion, or a manual “verified” checkbox is insufficient. Keep the initial branch single-physical-message/direct-sender; other nationally applicable branches retain explicit holds. No automatic conversion of existing agency9 roots.

A new point/site graph can carry an89 identity solely in the namespaced owner and retain nullable legacy ID fields, ONLY after the concrete readiness, Z03 rendering and persistence changes in revision 2 below. This avoids changing old global uniqueness semantics. An existing graph may retain its independently meaningful legacy fields, but those strings confer no89 authority. Existing89 data that cannot be bound by authentic process evidence stays held.

## Typed identity and immutable owner

Proposed new `lib/ediel/sources/meteringIdentityOwner.ts` contract:

```ts
type DistributorIdentity = {
  agency: '89'; identifier: string; // exact decoded C212/7140; no trim/case fold
  assigningGridOwnerId: string; assigningEdielId: string;
};
type MeteringIdentityBinding = {
  version: 1; companyId: string; environment: 'test' | 'production';
  identity: DistributorIdentity;
  bindingId: string; meteringPointId: string; siteId: string; customerId: string;
  sourceMessageId: string; sourcePayloadHash: string;
  messageIndex: number; physicalOccurrenceOrdinals: number[];
  originatingRequestId: string; originatingZ01Id: string;
  originatingZ01PayloadHash: string; returnedLineItemReference: string;
  effectiveFrom: string; effectiveTo: string | null;
  capturedAt: string; availableAt: string;
};
```

`effectiveFrom` is backed by the actual qualified business source, not an arbitrary supplied date; where Z02 contains no independently proven earlier assignment date, begin supported correspondence at capture. Keep `capturedAt` and availability DB-owned. This intentionally holds earlier89 history. Do not reinterpret Z02 message creation date as identity-assignment start.

Store append-only events in a new private `gridex_received_sources.metering_identity_bindings` table. Tenant/environment/agency/exact text (deterministic byte-sensitive comparison)/issuer form the identity key; point/site/customer UUIDs are graph targets, not wire identifiers. Include original sealed proof, actual applied request/job and actor attribution. All tenant graph links require composite checks. One active binding per key/time interval; the same point cannot acquire conflicting89 identities for the same issuer/time merely via retry. Explicit revisions reference predecessor; conflicts/overlaps reject. Reuse the assessment availability pattern for known-as-of reads; avoid mutable `active` flags retroactively changing old snapshots. Implement transaction serialization or a suitable exclusion/uniqueness scheme, not an application-only overlap check.

Restrict writes to a private verified capture function; no authenticated/service arbitrary table insert. A service entry RPC must rerun authorization and producer checks. Same source/correlation/content retry returns the same binding; different content under one source identity rejects. Updates/deletes reject. Tenant RLS/privileges and private helper revocations follow retained source-owner infrastructure. Do not backfill a row for every plain alias.

### Storage obstacle that an alias table alone does not fix

Current schema has `ux_customer_sites_company_facility` on normalized facility ID; `ux_metering_points_company_meter_id` on normalized meter ID and `ux_metering_points_company_metering_point_id` on plain ID. Nullable ID columns permit a bounded new namespaced graph without populating these legacy aliases. Use genuine internal UUIDs and exact89 identity in the new owner; never invent prefixed/suffixed “external IDs” to satisfy these indexes. Retain existing indexes for legacy rows. The new branch must bypass legacy onboarding normalization (`canonical_onboard_customer_graph`) and plain-alias uniqueness searches ONLY through an explicit namespace-aware producer, while preserving relational/customer conflicts. Audit triggers/callees in the implementation before enabling this branch; if any force a non-null legacy identifier, add a narrowly typed namespace alternative instead of dropping constraints globally.

## Concrete capture transaction

1. Open the genuine site-specific request and inboundZ02 under tenant/environment locks; locate the one actual originatingZ01 and retained LI registry. Require supported canonical Z02/expected variant, required payload and freshness owners. Locate sealed inbound original and bind the precise physical LIN. No parsed-payload preference.
2. A private release/UNA-aware projection independently extracts inbound BGM/function/subtype, FR/DO/UNB, LI, exact LIN ID+agency, physical scope and applicable original date fields. Use `closure_wire_tokens_v1` as a reviewed lexical building block, with a separate Z02/identity structural projection; the closure projection itself is not a generic identity verifier. Bind outbound Z01 original/correlation/parties independently too, from a retained immutable original or a DB-sealed copy captured before proof publication. Caller hashes alone do not establish source values.
3. Require actual direct senderFR==UNB sender; assigning grid owner is the active, environment-qualified request/site owner and its exact Ediel identifier matches FR. Receiver must qualify through existing tenant identity owner. Require the originating Z01 to contain the exact89 identifier and agency already supplied to its request, with the assigning owner as recipient. Compare that full tuple with Z02. Unknown-ID Z01 bootstrap is excluded: P47/field209 requiredness and P120 do not qualify it. The local point may be absent, but the requested external identity may not be inferred from the response or replaced by a placeholder.
4. Use the process-bound target point if the request already identifies one and all graph constraints agree. Otherwise create a new point on that exact request site (nullable legacy aliases), with the previously requested exact89 identity confirmed by the response. A manually selected arbitrary existing point is not sufficient correspondence. Any existing contradictory identity/site ownership holds.
5. Atomically commit graph outcome and binding. Private append verifies actual written point/site/owner plus all correlation sources. A source changing concurrently, rejected gate or graph write failure rolls back both. Capture failed/unavailable outcome through existing operational review path; do not publish a binding.

This is reuse of an actual market-response producer, not invention of an external mapping service. It supports newly witnessed exact correspondence and genuine retained reprocessing. Whether old records contain adequate originals is a per-record evidence question.

### R2.2 Stable identity key and durable quantity isolation

Use a versioned structured identity key, not concatenation of user strings with `|`. Example canonical typed tuple: `[2,companyId,environment,'89',exactIdentifier,assigningGridOwnerId,assigningEdielId,meteringPointId]`. Stable correspondence key differs from binding-event UUID: a later proof revision of the same correspondence must not accidentally fork a series, while reassignment to a different point must not inherit its predecessor. Store binding event UUID and proof/source/cutoff separately for audit and replay. SQL constructs the canonical key from validated originals/rows; caller key/hash cannot authorize it.

Concrete call chain:

1. `lib/ediel/flows/utiltsDataRequest.part-1.ts` (`UtiltsTransactionMatch`, transaction matching) must read exact original LOC identity/agency and relevant legal-party scope per physical transaction, not `stringOrNull`/normalized identifier-only matching. Resolve the assigning owner through the qualified direct-grid-owner branch and immutable binding. Carry transaction index/reference, typed key, binding ID and point/customer/site. No message-level point fallback for89.
2. `utiltsDataRequest.part-2.ts` and `utiltsInboundPolicyProcessor.ts` must require this attribution before any individual-point89 quantity persistence, including high-resolution energy where structural comparison legitimately returns `not_applicable`. `matches:[]` in non-billing persistence must not invent an individual89 point. Unsupported non-billing aggregate identity remains its existing separate kind, with no grant of89 authority.
3. `lib/ediel/utilts/transactionPersistence.ts`: extend both match and persistence-item types with discriminated attribution version and exact identity/binding proof. Include it in the shared successful-retry consumption contract. Missing/unqualified89 proof becomes internal review with no quantities, not an invented national ERR. Preserve existing ACK reservation decisions and finalized responses.
4. A forward SQL revision of `gridex_persist_utilts_transactions_v1` independently projects each original UTILTS transaction's LOC/agency/issuer scope from sealed source using bounded release-aware parsing and validates binding+point+tenant+environment/effective interval/knowledge cutoff. Do not merely compare submitted JSON with itself. Invalid identity proof cannot return an existing successful series ID.
5. Persist explicit `identity_key_version` and qualified identity key/proof on `meter_reading_series` (columns or strictly validated private companion row). Version2 series lock, dedupe hash and **previous-series selection** all include this exact same stable qualified key, plus existing seriesKind/messageCode/gridArea/period/resolution/product dimensions. Dedupe additionally includes transaction identity under existing semantics. The conflict-return branch compares validated identity and full successful-retry consumption fingerprint before returning the old series. Include high-resolution energy, wrong caller point/issuer, forged same-hash identity, legacy series present, source mutation and successful-retry attribution mutation. Same exact correspondence retry remains idempotent; legitimate correction supersedes only its own series.

### R2.3 Time model and sequencing

`qualifyReceivedStructure.ts` currently opens a fresh processing-time snapshot on each invocation. Preserve that explicit knowledge cutoff; do not silently change to receipt-only qualification. Saved historical snapshots remain immutable. A later binding can inform a fresh retry only where its proven effective interval covers the target data/business date; capture without earlier assignment evidence starts effective support at capture and therefore cannot repair arbitrary historical data. A previously successful consumption remains bound to its original source+attribution contract even if a newer current binding differs. The retry owner and identity owner must share this rule before activation.

Implementation sequence remains bounded but end-to-end: source-bound suppliedZ01/Z02 owner and nullable graph transaction; typed readiness/Z03 and actualZ04 root; reviewed structure plus mandatory UTILTS key/persistence/replay isolation. Keep89 held until the complete selected branch passes real construction, native isolation and independent re-review. No partial step is universal E035 completion.
