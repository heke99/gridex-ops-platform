## Supported first capture: sealed inbound Z05 original

Use `gridex_received_sources.sources` as the first immutable original, keyed by `source_message_id`. `20260922095911_ediel_received_source_ledger.sql` captures inbound EDIFACT PRODAT in an `AFTER INSERT` trigger, after `gridex_validate_ediel_message_contract` seals `raw_payload`, SHA-256 and insertion context. It records company, environment, message code, received/captured times, raw bytes/hash and `received_context`; there is no cascade FK from mutable `ediel_messages`. Older rows were deliberately **not backfilled**. The trigger and source table reject mutation; a mutable message status, parsed payload or uploaded copy is not the original.

Provide a new server action near `app/admin/ediel/structure-actions.ts` accepting **only** `companyId`, `environment`, `sourceMessageId` and an explicit “record for review” confirmation. It calls `requireCompanyScopedActionAccess(companyId,{allOf:['communication.write']})` and `requireCompanyOperationalForWrites(companyId)` before service reads/writes; `lib/admin/guards.ts:299` verifies active writable company membership, while its permission model treats a bare array as `anyOf`. `communication.write` is an ordinary operational communication-capture capability, **not** the later `closure_process_evidence.review` interpretive permission. Use `context.userId` from the guard. This is an operational candidate registration, not the existing `reviewReceivedClosureAction` (which accepts only L/LK and allows `ediel_testing.write`). A test-only bypass must not become production review authority.

The service resolves the source by company/environment/ID and checks `origin='database_insert'`, inbound PRODAT/EDIFACT, `message_code='Z05'`, non-null raw/hash/context and original byte/hash parity. Independently inspect original physical BGM/Z05, CCI/CAV Z24, object/agency, LI, DTM93 and parties under the existing bounded UNA-aware parser primitives (`closureSourceWire.ts` is L/LK-only, `closureImpact.ts` is a conservative impact projector). Unsupported/malformed or ambiguous scope can still be captured as a **concern** with wildcard/unknown scope and whole matching interval hold; it cannot become positive C or an asserted exact target. Never infer target from LI alone. Check any supplied target reference against a separate sealed L/LK source and current witnessed closure by tenant/environment, exact object/parties/old stop and source hash; absent target remains unresolved, rather than preventing raw C visibility. SQL must independently re-read sealed originals and validate the stored raw observations; TypeScript parse output is not a transferable authority.

Create a private append-only concern row containing `source_message_id`, source payload hash, tenant/environment, observed database-derived scope, original source receipt/capture and concern-capture commit times, typed old/proposed boundary observations (`known`, `not_asserted`, `unknown`), optional **unqualified** candidate target, and `disposition='unreviewed'`. For a bare C with known old stop but no changed-date assertion, proposed is `not_asserted`; an artifact indicating a changed end without a reliably read date is `unknown` and must hold the whole matching interval. Do not accept caller-provided bytes, SHA, legal issuer, corrected date, reviewer or approval. Idempotent same-original retry must return the same concern without losing an intervening revision; changed facts append a new revision, never overwrite it.

The capture RPC must be service-only, with tenant/environment and original checks in SQL, RLS/forced RLS, revoked direct DML and immutable update/delete/truncate triggers. It can record the server-authenticated action actor ID and independently verify current company `communication.write` via `gridex_actor_has_company_permission`, but an arbitrary client-supplied actor ID must not be accepted by the exposed server action. A separate **post-commit** witness observes the already committed concern ID/hash, company/environment and visibility time; same-transaction append is not a witness. The response is a typed `{captureId,sourceMessageId,sourcePayloadHash,scopeHash,capturedAt,availableAt}` only after readback and witness validation. A failed/unknown witness returns `unconfirmed` and must not be reported as successful, while the raw sealed C remains discoverable as a hold from its own received-source visibility. No `approved` basis column or positive C SQL branch belongs in this slice.

## Document route: context only, not an initial correction-confirmation producer

`lib/customer-contracts/documents.ts` exposes `getCustomerContractDocumentById` and `downloadAndVerifyCustomerContractDocument`. The latter fetches stored bytes and checks SHA-256 against `customer_contract_documents.document_sha256`; `app/api/admin/customer-contract-documents/[documentId]/route.ts` requires `documents.read` and `customers.read`, then separately `assertCompanyAccessForGuard(document.company_id, access.guard)` before download. Reuse **that tenant check and readback pattern**, not the public download route as a privileged capture API. The service must additionally join `customer_contract_documents.customer_contract_id` to the selected customer/contract/point/supply graph and verify company scope, MIME/length and actual bytes. Its archive helper can take a supplied hash and writes metadata; `onlineSigning.ts` binds a signing snapshot, but neither establishes that an old termination was erroneous. `customer_documents` metadata, URL, OCR, `verified_at`, filename or signature alone are not an authenticated network-owner correction confirmation.

Safest initial supported input is therefore the sealed Z05 original by ID. If a signed contract PDF is later attached as **supporting context**, retrieve and copy its verified bytes into bounded private storage with DB-computed SHA and source ID/hash; do not label it independent cause/provenance or silently turn it into an accepted basis. An external counterparty correction document needs a separate authenticated channel/signature/known-contact record and narrowly permissioned provenance review; no such producer was established by these document APIs. Task 2 can keep that method unavailable while still capturing the raw C concern.

## Retention and verification boundary

`gridex_data_retention_policies` already lists `edifact_raw_payloads` as 1095-day **archive**, `legal_audit` as 3650-day archive, and `ediel_polling` as 395-day delete (with an explicit note that canonical messages/raw evidence follow a separate archive policy). The sealed Z05 reference is raw EDIFACT evidence; do not classify it as polling telemetry. These category rows do **not** prove actual storage/archive coverage, authorize indefinite retention, or automatically assign newly copied correction PDFs to `legal_audit`. Keep any new concern metadata under an explicitly reviewed existing lawful evidence policy or mark its retention classification unresolved before document-byte rollout; record actual coverage start/end and missing spans. Missing old outbound Z08H dispatch, customer/contract process inception, or purged originals remain scoped unavailable. Never backfill a fictitious complete interval from current rows.

Targeted Task 2 probes: no C/unknown LI, matching and forged source hash, cross-company/environment, inactive actor, `communication.write` absent, unsupported physical envelope, direct table/RPC attempt, source deletion/ID reuse, byte substitution, same-transaction witness, interruption after append, saved pre-capture cutoff, and null versus known boundary. A genuine signed PDF test proves byte and tenant/contract linkage only; its “positive” fixture must still fail semantic-correction approval. No real market send, hosted DB mutation or positive C acceptance is needed for this first capture method.
