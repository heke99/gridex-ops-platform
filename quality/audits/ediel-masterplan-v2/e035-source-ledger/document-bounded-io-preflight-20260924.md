# E035 Task 2b: bounded signed-PDF readback seam

Read-only implementation preflight, 2026-09-24. This is the context-only reference in `e035-document-reference-design.md`, never a positive correction cause. No network read or code/schema/test change was performed.

## Existing seam and installed API

`lib/customer-contracts/documents.ts:154–188` currently awaits `supabaseService.storage.from(bucket).download(path)` and then `data.arrayBuffer()`, so the whole response becomes a Blob/Buffer before the SHA-256 check. Its `verified_at` update is best effort and is not a capture receipt. The same helper serves `app/api/admin/customer-contract-documents/[documentId]/route.ts` and `lib/website/customerApplicationCommunication.ts`; changing its return/ordinary download behavior would affect those callers.

Installed `@supabase/storage-js` **2.103.0** supports `.download(path, {}, {signal, cache:'no-store'}).asStream()`. Its type returns `ReadableStream<Uint8Array>` and its bundled implementation returns the `Response.body` without calling `Response.blob()`. Without `.asStream()`, the builder calls `Response.blob()` and defeats the cap. The third download parameter passes the `AbortSignal` to fetch; storage client service credentials and private bucket access remain inside the existing server-only service client. Do not create a signed URL, log a locator/token, use a transform, or call the public HTTP document route.

## Small helper extension and caller order

Add a distinct `downloadAndVerifyCustomerContractDocumentBounded(document, {maxBytes:2_097_152, timeoutMs:<fixed reviewed budget>})` in `lib/customer-contracts/documents.ts`, preferably with a private shared digest comparison routine; leave current general-purpose download API intact. The helper accepts a previously resolved immutable row only from a server-owned capture action. Require `document_type='signed_contract_pdf'`, exact private bucket, non-null locked `storage_path`, MIME `application/pdf`, valid expected SHA, and row/company/contract values. Do not trust a supplied object path/hash. The capture action first derives authenticated actor and current company permission (`communication.write`, `documents.read`, `customers.read`), validates sealed Z05 source/company/environment and joined contract/customer/site/point/supply linkage in SQL, and commits the scoped unresolved attempt **before** storage I/O. `getCustomerContractDocumentById` is an unscoped metadata lookup; a company predicate/join and SQL recheck must precede the private download. Foreign-tenant failure must not reveal document details. Future interpretive review permission remains separate.

Use `AbortController` with a fixed 10-second operation deadline spanning fetch and full body read (adjust only after measured native/runtime qualification). Race the fetch/read operation against the deadline as well as passing its signal, so an adapter that ignores abort cannot leave the capture action hanging; the deadline loser must abort/cancel, and any late result must be discarded. Await the builder **as a stream**, then `getReader()` and loop. For every chunk, add its actual byte length, abort/cancel and throw at `>2_097_152` before retaining or hashing that chunk; at the exact limit, continue to EOF, since an additional byte must fail. Hash each allowed `Uint8Array` incrementally with `createHash('sha256')`, retain chunks only up to cap if a Buffer is needed, and compare final hex digest against `document_sha256` as the existing helper does. An expected-size header or document metadata may reject early but cannot establish success. On timeout, error, overflow or mismatch, cancel the reader/abort the controller without waiting indefinitely for a stalled cancel; return an unavailable result attached to the already committed attempt. Clear the timer in `finally`; check `signal.aborted` before declaring verified. A stream with no body, truncated stream that errors, or abort during read is unavailable. Storage-read start/end, byte count/hash and later DB outcome/committed witness remain separate observations; no false storage-continuity or historical coverage is inferred.

This path can return a bounded `Buffer` if the capture owner needs bytes transiently; the context reference should persist only locked document ID/hash/link and readback observation, not a duplicate PDF. Do not set `verified_at` as the receipt or require it for authority. If the legacy helper's optional `verified_at` update is shared, failure of that update cannot convert a real hash check into a signed capture witness. The new outcome append itself must succeed and later be independently witnessed; interruption leaves the initial unresolved attempt visible. Keep the limit specific to E035; the bucket's existing 10 MiB upload rule and ordinary authorized download remain separate.

## Bounded oracles, without live storage

- Inject/mock the Storage builder (or a narrow internal stream reader) using `ReadableStream<Uint8Array>`: exact 2 MiB in many chunks succeeds with matching SHA; 2 MiB+1 aborts and cancels before accumulation; a declared small length with extra bytes fails; a large first chunk does not get buffered.
- A never-resolving fetch and a stalled body read each hit the same deadline and abort; an abort race cannot return verified. Body error, missing body, hash mismatch, Storage error and pre-connect rejection become unavailable while the prior unresolved concern remains.
- Assert `.asStream()` and third-argument `signal` are used and `Blob.arrayBuffer()` is never called. No real service credentials or URL are printed. Exercise a non-ASCII/multiple-chunk byte sequence to prove byte-exact SHA, not text normalization.
- Before the mocked stream is invoked, wrong company/contract/source/environment, revoked actor, missing row/path/type, or ambiguous point/supply graph must fail at the action/SQL boundary. Existing ordinary download callers retain their behavior. Newer process readsets re-fetch/re-hash; deleted/replaced storage bytes or pre-epoch missing history hold, and an earlier saved readset is not rewritten.

The installed client API makes true streaming and cancellation available. Native verification must confirm that the deployed runtime honors fetch abort for both header and body stalls; a failed or non-aborting read is an unavailable context outcome, never a verified receipt.
