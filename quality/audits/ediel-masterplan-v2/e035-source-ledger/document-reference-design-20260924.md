# E035 signed-document reference as context-only evidence

Read-only design alternative, 2026-09-24. Parent-authorized sealed-Z05 capture proceeds separately. This evaluates an optional **reference**, without copying PDF bytes into a new archive or approving correction cause/provenance. No code/schema/test/plan edit, commit, hosted read/write or market send was performed.

## Verdict

**Implementable for a weaker context-only reference, subject to fail-closed byte revalidation and explicit coverage limits.** A stored `customer_contract_documents` ID plus its locked company/contract/type/bucket/path/MIME/SHA/generation snapshot, and actual `downloadAndVerifyCustomerContractDocument` readback, can identify a particular signed-contract PDF at one storage observation. It is **not** the approved retained-byte original artifact for positive process-basis authority. It cannot itself show the network owner said an earlier Z05 end was erroneous, establish independent correction provenance, or prove permanent/historical availability. If current bytes or linkage cannot be verified, the already recorded relevant unresolved concern/retention gap holds; never fall back to `verified_at`, metadata, a URL or another PDF. The process-basis positive branch stays disabled.

## Actual guarantees and gaps

- `20260716183000_contract_canonical_finalization.sql:1490–1526` creates the private `customer-contract-documents` bucket, a unique bucket/path index and `gridex_lock_customer_contract_document`. It forbids DELETE and, **once `old.storage_path` is non-null**, changes to company ID, contract ID, document type, bucket/path, MIME, SHA and generation snapshot. `generated_at`, `archived_at` and `verified_at` are not in that comparison; do not treat those timestamps as immutable evidence time. A row with null `storage_path` lacks this strong identity lock and is ineligible for reference capture. An earlier migration's blanket immutable trigger was replaced by this conditional one.
- `lib/customer-contracts/documents.ts` uploads to a content-addressed tenant/contract path with `upsert:false`, then records the document row. `downloadAndVerifyCustomerContractDocument` downloads current bytes and computes SHA-256 against `document_sha256`. `archiveSignedCustomerContractPdf` can accept a supplied digest, and its existing-row fast path returns metadata without readback; neither action alone is capture proof. The readback helper may update `verified_at`, which is mutable and not the evidence cutoff.
- The inspected app code has no routine `.remove()` or overwrite of this bucket, and the bucket is private with a 10 MiB PDF limit. That is **not** a database immutability guarantee on `storage.objects`: service-role/admin storage deletion or replacement and an external retention workflow remain possible. The inspected migrations did not establish a specific storage-object update/delete prohibition for this bucket. A metadata-row lock and `upsert:false` on one writer cannot prove object persistence. No claim that a SQL comment saying “permanent archive” overrides lawful retention.
- `onlineSigning.ts:512–555` generates a PDF from the online signature receipt, computes its SHA, archives it and records signature request/contract/pricing/legal snapshot references. That can support a contract fact. `20260831095000_admin_signed_contract_import_canonicalization.sql:417–458` can also create a document row from an admin imported signed document. Therefore `document_type='signed_contract_pdf'` does not uniquely mean an online-signing provenance chain; require the exact declared `generation_snapshot.schema` and corresponding source evidence if later deciding signature origin. Neither route is the independent counterparty correction confirmation required for positive C.
- `app/api/admin/customer-contract-documents/[documentId]/route.ts` requires `documents.read` and `customers.read`, then checks `assertCompanyAccessForGuard(document.company_id, access.guard)` before download. A new server-owned capture action must apply its own company/environment and selected contract/customer/supply linkage; do not call the HTTP download route as a privileged shortcut. `getCustomerContractDocumentById` alone has no company predicate, so compare its result and join `customer_contracts.company_id`/customer to the target graph before any bytes are returned or referenced.

## Small, implementable reference contract

After the sealed Z05 source has been captured, a server action may accept only `companyId`, `environment`, `sourceMessageId`, `documentId` and confirmation. It derives the **authenticated actor ID from its server session**, never from the form. Require active company-scoped operational capture access (`communication.write`) **and** document/customer read rights, using `{allOf:['communication.write','documents.read','customers.read']}` plus `requireCompanyOperationalForWrites`. These are capture/read rights; future interpretive `closure_process_evidence.review` remains separately permissioned and unavailable. The service resolves source and document, joins the exact tenant contract/customer/site/point/supply graph, and checks the document row's company and contract before reading bytes. A contract document has no environment of its own: bind environment through the sealed Z05 source and graph. Missing or ambiguous links remain scoped unresolved, never guessed exact matches; a foreign-tenant document is an authorization failure and must not disclose or create a concern about that document.

After authenticated tenant-safe relevance is established, **persist an unresolved concern/attempt before storage access**. Then a bounded download wrapper reads the selected `signed_contract_pdf`, using `downloadAndVerifyCustomerContractDocument`'s actual byte/hash check and an operation-specific cancellable time budget. That helper currently buffers the full object; if the storage client cannot enforce cancellation or a safe read budget, a timeout is an unavailable outcome, not a verified receipt. Capture eligibility is **at most 2,097,152 actual bytes (2 MiB)**. Check the returned `Buffer.byteLength` and independent SHA, not `Content-Length`, MIME or metadata alone. A 2 MiB object may pass; 2 MiB+1 fails, including a PDF valid under the bucket's separate 10 MiB limit. The bucket upload policy is not changed. Missing bucket/path, wrong type, timeout, oversize or mismatch appends an unavailable result against the existing concern. Do not accept caller-supplied path, digest, correction date, legal sender or semantic assertion.

Append private, closed-shape `context_document_reference_v1` **attempt and outcome revisions** with source ID/hash, document ID, company/environment, contract/customer/site/point/supply link, locked bucket/path/type/MIME/SHA/generation-snapshot hash, authenticated action actor, status `unresolved|verified_at_observation|unavailable`, and predecessor. Private tables use forced RLS, no direct client or service DML, narrow service-only wrappers and append-only update/delete/truncate protection. SQL independently checks the sealed source, document row and full same-company graph in one MVCC statement and rechecks the derived actor's current company membership and all required permissions; a generic service-role connection does not authenticate a browser session, so the trusted server action derives actor identity and never accepts a caller-chosen actor UUID.

Record **separate times and meanings**: storage-read start and completion with observed byte count/SHA; database transaction ID/server record time for the appended attempt/outcome; and a later, separate transaction's committed-row availability witness with its own observed time/visibility token. DB `now()` before commit is not commit visibility. The witness proves the receipt was committed and observable, **not** that PDF bytes existed at DB commit, remained present between reads, or still exist. A second storage read gets its own start/completion/hash observation and cannot establish interval continuity. SQL cannot inspect storage bytes; the server-observed hash is a bounded observation, not SQL-certified original content. `generated_at`, `archived_at`, `verified_at` and signing date remain described document/business times, never acquisition/knowledge cutoff. No content locator, issuer authentication or cause statement is accepted by this operation.

On every new process readset/review that would rely on the document content, re-read the exact locked row and download/rehash current bytes within the same 2 MiB/time budget. If missing, changed, wrong tenant, source/contract graph changed, storage read times out, witness is lost, or retained interval from process inception is unprovable, return scoped `document_reference_unavailable`/history-incomplete. The attempt/concern remains visible even when retrieval, verification or later witness fails; if the initial attempt cannot commit, the process reader must report incomplete rather than omit a known candidate. Raw, rejected, unwitnessed and lost-byte concerns join every newer applicable cutoff. With no trusted corrected date they hold the matching supply/object interval conservatively; they cannot clear an earlier hold. A saved earlier readset preserves its original cutoff, row fields, hash and recorded verification outcome without being rewritten by later loss; it does **not** promise an auditor can retrieve old PDF bytes after loss. Fresh positive semantic assessment remains outside this reference owner and requires the approved retained-byte artifact and independent provenance.

Bounded tests: existing locked row versus null-path row; upload with `upsert:false` and same path attempt; attempted row SHA/path/tenant edit and DELETE; storage replacement/deletion before append, between append and witness, and after witness, with every new read holding on loss; wrong tenant/contract/customer/site/point/supply and environment, stale/revoked actor and direct DML/RPC denial; admin-import versus online-signing origin; verified PDF with no external correction stays non-authoritative; 2 MiB acceptance, 2 MiB+1 rejection and a 10 MiB bucket-valid but capture-ineligible PDF; read timeout, hash mismatch and interruption before outcome append still leave the prior unresolved attempt visible; interruption before attempt commit makes the reader incomplete; rejected/unwitnessed revision at a new cutoff holds, old saved cutoff remains unchanged; missing historical PDF or process-inception coverage remains unavailable. A PDF readback pass is a context identity result, never a positive Z05C result.

## Retention decision

The existing `legal_audit` 3650-day archive and `edifact_raw_payloads` 1095-day archive policies describe categories, while `ediel_polling` is disposable telemetry. They do not prove this PDF's actual storage interval or assign a new legal duration for a copied document. The reference-only form creates no duplicate byte-retention class; it relies on the contract document's existing lawful storage, with actual availability/coverage checked per instance. Before any positive historical-process claim, record the document's observed coverage start and missing spans and obtain the applicable retention-class/archival owner decision for that underlying contract store. Do not backdate a capture to signing time or ask for a generic permission to proceed with hold-only engineering.
