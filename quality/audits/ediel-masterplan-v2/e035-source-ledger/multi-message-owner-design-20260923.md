# Multiple physical PRODAT messages — bounded owner design

2026-09-23 revision 2 (MM-1 outer orchestration amendment). Read-only proposal for independent design review before implementation. No code, schema, tests, frozen source manifest or masterplan changed. Uses the completed single-message owners as contracts, not as evidence that a later UNH already passed them. Writing-plans informs the scope and proof obligations; no new agents or broad audit/test execution.

## Source basis and selected boundary

Frozen P26.A r3 SHA256 `83c2f1d2915851d2e670731f6ab404ef06c9b9def282afbafdfa0eda836a6e95`, actual p14: BGM1001 carries function excluding subtype; different PRODAT functions cannot share one interchange. P47 restarts field314 per message; register258 belongs to its object. Frozen T24-A-6 SHA256 `5204d4514774b04b8eedb039e1f4799ed447c7fef14554577935e2d7bd93f951`, actual2.1.2p13 requires UNT segment counts, UNZ message count, matching UNH/UNT and UNB/UNZ references and separator handling. T4.3.1p25 defines UNZ0036 as message count. These qualify multiple same-function messages, not mixed Z04/Z06 positive fixtures. P14 also calls for orderly original/cancellation processing. They do not establish previously missing business outcomes or full UNSM certification.

Initial implementation boundary: same BGM function, one tenant/environment and one envelope, direct sender, already-supported agency9 and supported subtype/lifecycle owners. It must admit two valid same-function physical messages end-to-end; merely removing `singleMessage` is insufficient. Each UNH resolves its own subtype/rule pack, BGM document/function1225, LI, dates and parties. Different subtypes do not automatically mean different BGM functions. Unsupported subtype/agency/delegation is represented as unavailable, never silently discarded. Agency89 work remains a separate typed owner dependency.

## Exact physical contract and limits

Proposed `core/prodatPhysicalEnvelope.ts` builds a checked token-view model from that original:

```ts
type PhysicalMessageScope = {
  sourceMessageId: string; sourcePayloadHash: string;
  messageIndex: number; messageReference: string;
  unhSegmentIndex: number; untSegmentIndex: number;
};
type PhysicalObjectScope = PhysicalMessageScope & {
  objectId: string | null; identityAgency: string | null;
  registers: Array<{
    segmentIndex: number; lineIndex: number; messageLineOrdinal: number;
    lineNumber: string | null; registerIndex: string | null; registerPosition: number;
  }>;
};
```

Preserve current global `segmentIndex` and global LIN `lineIndex`; explicitly add zero-based `messageLineOrdinal` rather than silently changing their meaning. Wire314 sequence starts1 per UNH; wire258/registerPosition restarts per object. Composite object key includes source/hash + physical message ordinal/reference + exact ID/agency; missing ID gets its exact physical LIN ordinal, not a shared null key. UNH references must be nonempty and unique within this bounded envelope; repeated/unqualified references hold/reject according to the actual syntax owner, never collapse into a map entry. Do not assume document ID or LI is globally unique.

Selected initial support limits (engineering budgets, not national maxima): original ≤262144 UTF-8 bytes; ≤512 total tokenized segments; 1–16 physical messages; ≤16 total LIN occurrences across the source; each element/component≤128 items and component≤4096 characters matching the private lexer bounds. Complete facts≤262144 bytes. Existing snapshot limits remain: ≤1000 sources, ≤128 assessments per source, input≤6291456 bytes, readset≤8388608 bytes, total inspected segments≤32768. Do not silently expand lower limits through a new reader. Budget violation returns explicit incomplete/unavailable and no positive completeness, never a prefix accepted as complete or a fabricated national error. Parse/validate all bounded messages before business writes. Keep finite per-owner read deadlines and a bounded source-operation deadline; timeout leaves unprocessed physical entries unavailable.

Envelope check: oneUNB first, oneUNZ last; exactly contiguous nonnested UNH...UNT ranges; no orphan body segments/UNH/UNT; exact UNH/UNT references and UNT count including both delimiters; UNZ count equals all ranges and its reference equalsUNB; all familiesPRODAT and same BGM1001. Syntax owner remains responsible for full national wire grammar. CustomUNA and released literal `UNH`/`UNT` data must not affect counts. Preserve canonical syntax numeric-format behavior rather than accepting arbitrary parseInt prefixes.

A physical view references original tokens, envelope context and scope. No synthesized raw string is passed to a legacy single-message validator as if it were the original. Refactor actual canonical/policy/parser APIs to accept this checked view. Whole-envelope syntax and each message's semantic fields are distinct inputs; legacy single-message callers use a one-view adapter. If a validator only accepts raw strings, add a token-view entry point before activating multi-message acceptance. AST `messages[n].lineGroups` currently re-groups a slice, so its locally recomputed messageIndex cannot be trusted as the global message ordinal without explicit rebinding to the envelope index.

## Outer orchestration barrier — required MM-1 amendment

Install the v2 barrier inside `lib/ediel/flows/inboundProcessing.ts::processInboundEdielMessage`, after original-row eligibility and genuine tenant resolution, **before** the existing single-source `applyCanonicalRuntimeDecision` invocation and its later syntax/internal-review/ACK/actor-testing early returns. A bounded delimiter-aware envelope inspection selects the route. One proven single message retains the current v1 path. More than one physical message enters only the v2 coordinator; malformed or budget-exceeded candidate envelopes never fall back to first-message v1 processing. An unreadable source cannot be classified as single-message merely because a prefix contained oneUNH.

The coordinator owns checked envelope validation, all per-UNH canonical invocations, scope-keyed owner-session collection, physical national response plans and one final full-composition `finish()` in `finally`. Refactor reusable canonical evaluation away from the existing parent-report mutation as needed; a v2 parent summary is diagnostic and cannot feed `prodatInternalReview`, `responsePlanItemFor`, `createAutomaticPositiveAcks` or any other first-source shortcut. Only after every physical scope has a recorded outcome does the coordinator return its aggregate parent result. Child processing returns to the coordinator loop, never from the top-level source function. Traces must report ordered physical results rather than imply first-child source acceptance.

Failure classification is explicit:

- Unresolved ingress route, invalid envelope syntax, unknown/incomplete physical membership or exceeded preflight budget blocks all multi-message writes. Retain the complete available diagnostic envelope state; use only already-qualified envelope response policy. Routing/budget uncertainty creates no invented negative CONTRL.
- An individual canonical application/functional/internal-review failure, legal party mismatch, unsupported subtype or business failure marks that checked message/object rejected or unavailable and proceeds to other preflight-independent scopes. It must not set a parent control flag that exits their dispatch. Valid independent child1 can genuinely commit while child2 remains held; source-complete remains false.
- Dependency/collision findings retain the affected scopes unavailable under the stated lifecycle limit. A runtime deadline or exception may stop further execution, but `finally` materializes every unprocessed scope as unavailable, not absent. Any committed sibling remains a real outcome.

**Chosen initial actor-testing boundary:** no multi-message call to legacy `syncActorTestingGlobally` or `syncActorTestingForMessage`, whether once per parent or once per child. In particular never invoke them to discover eligibility: the existing hook may already auto-respond/auto-send before returning “handled.” The v2 coordinator uses a side-effect-free read of the actual test configuration/candidate owner to classify actor-testing interception. A configuration positively requiring actor-test handling, or an unresolved candidate classification in a test route, receives explicit `multi_message_actor_testing_unavailable` on the affected complete physical composition after per-message inspection; no automatic actor-test business operation or market response is attempted. It is not marked handled/accepted. Ordinary supported processing can run only when the candidate owner establishes that actor-testing interception is not required. Merely `environment='test'` is not permission to run the old hook, nor evidence that an actor-test response was sent.

This is an explicit temporary exclusion of automatic multi-message actor-testing, not a new interpretation of national message validity. Full scope-aware actor-testing would be a separately qualified adapter using physical canonical decisions and response keys; it cannot be enabled by calling the old parent-row hook with a new DTO. The v2 owner loop must still inspect/retain all physical messages under actor-test candidate conditions, recording held entries and final composition rather than exiting on a first-message sync result. Legacy global automatic ACK creation and any later global autoSend hook remain unreachable from the v2 path.

Top-level integration proofs must enter through `processInboundEdielMessage` with genuine route/configuration owners: (1) two same-function messages, child1 actual switch/supply commit and child2 canonical internal-review failure; observe both full physical decisions, exactly one operation and no parent early return hiding child2; (2) the same envelope under actual actor-testing candidate conditions, asserting neither global sync hook nor automatic send/response builder is called, every child remains represented with explicit unavailable actor-test handling and no false source approval. Also prove ordinary non-actor-test test-route processing and the unchanged v1 path. Helper-only tests are insufficient.

## Canonical, routing and business owners

1. Resolve ingress tenant/environment from the genuine original UNB route as today; every physical FR/DO and selected point owner must match that tenant's qualified legal/transport receiver and supported sender owner. LaterNAD never reassigns tenant. Reject/hold later mismatches individually; no cross-tenant point lookup or write. Preserve test/prod and subaddress holds.
2. Run envelope syntax once and live registry-backed application/functional validation separately for every checked UNH. The rule selector consumes that message's BGM/subtype/date/party context, never the first row's parsed payload or cached rule report. Keep complete physical facets, including messages with no LIN, invalid LIN IDs or missing headers. An empty object list cannot make a message vacuously approved.
3. New canonical facts v2 contain checked envelope membership plus ordered `messages[]`, each with physical scope, syntax/application/functional decisions, actual rule-pack evidence and register facet. Overall summary is conservative and is not used to overwrite individual states. One-use seed carries the whole original and detached v2 facets; SQL independently validates physical membership. SQL does not pretend to rerun TypeScript rules, but validates actual registry identities and original value binding as in the retained contract.
4. `processInboundProdatMessage` receives a checked scope/semantic view for each operational invocation. It must not repeatedly call `recognizeInboundFacilityData`, canonical link, Z02 handler or legacy parser by source ID and thereby reprocessUNH0. Add scoped entry points to those used by the selected lifecycle; unsupported handlers retain unavailable outcomes. Parent `ediel_messages.customer_id/site_id/metering_point_id` are not a multipoint authority and must not be overwritten with each sibling's link. Store real per-physical associations separately; preserve parent diagnostic summary only.
5. For Z04, match that object's real outboundZ03 by its own LI/exact identity/parties/tenant and process rules. Add private durable operation association keyed by full physical object scope plus operation kind, storing switch/supply/customer/site/point and committed outcome. Link to actual business writes within their transaction or qualify the association only after independent database checks of the genuinely executed operation. For reliable crash recovery, prefer a bounded transactional Z04 apply/capture entry; merely inserting an association after arbitrary rows look accepted cannot manufacture the missing fresh commit. SQL original projection must bind its LI/date/object/party to the original physical message and outbound case.
6. Publish an ephemeral `SourceSwitchCommit` carrying full scope and operation association ID only after that physical operation commits. The v2 session maintains one entry per complete physical object and consumes every legitimate callback, rejecting duplicate contradictory outcomes. It must not persist-and-close on the first callback. `finish()` persists all entries once (including untouched unavailable siblings), and then obtains a separate committed availability witness. Recovery uses a genuine durable operation association or an explicitly rerun idempotent operation; cached status/foreign-key equality alone is not a recovered capability.

Same-object messages or two messages targeting one switch/supply can be dependent. Preflight collision detection must hold them unless the supported lifecycle explicitly orders and proves each transition. Do not execute them concurrently or treat two original Z04s as two roots. Replacements/cancellations in one envelope require qualified dependency ordering and distinct predecessor references; the initial bounded implementation may hold that branch while preserving both physical entries. This is an engineering support limit, not a national prohibition.

## Partial writes, ACKs and source completeness

Envelope syntax/tenant failure or incomplete physical membership prevents all new multi-message business writes. After complete preflight, an independently canonical/party-qualified message may commit while another independent message fails application/business validation. Successfully committed operations are not rolled back merely because evidence persistence later fails; their owner entry remains unavailable until a genuine recovery proves it. Never replay already committed siblings as new operations. No partial business result grants approval to another object or the source.

Source-complete v2 means: full envelope membership known; all physical messages have qualifying canonical facets; every applicable object has accepted party and actual business/review owner; no unsupported/no-LIN/malformed/unprocessed sibling; complete accepted assessment committed and separately witnessed. `objects.every(...)` alone is insufficient. Store this derivation explicitly in the source composition; no caller can assert it directly. An intermediate all-objects snapshot may be retained with accepted/rejected/unavailable entries, but full source disposition remains not_established.

ACK construction is an activation dependency. `inboundProcessing.ts::responsePlanItemFor/createAutomaticPositiveAcks` currently selects one family plan; current lifecycle aggregation keys source/family/scope/reference/outcome rather than a checked physical message identity. Carry each canonical plan's actual UNH reference/physical scope into response construction and durable idempotency, preserving the original envelope reference. Envelope CONTRL and message/application responses must use their existing qualified national policy; never clone the first APERAK for allUNHs, invent a LI or send multiple envelope ACKs by looping the old handler. Add exact physical key to any response uniqueness/reservation path that would otherwise merge siblings, including `core/kernel.ts::createCanonicalAckMessage` and its preflight/conflicting-outcome guard. Preserve immutable finalized positive/negative outcome per physical response scope; one sibling must neither suppress another nor permit an opposite already-sent response for itself. Envelope CONTRL remains one envelope response. A national response decision is separate from source-owner completeness; internal evidence unavailability cannot create a new national rejection. If the existing response renderer cannot express correct physical scope, hold activation of automatic multi-message processing until that path is implemented and tested. This task sends no market messages.

## Immutable ledger, original SQL scope and selection

Forward v2 validation/object-assessment branches preserve the existing immutable source row, original source hash, append-only assessment predecessor chain and separate witness. A full composition includes every physical message and object; per-message progress does not create unrelated source histories. Appending a review for one object must retain siblings' qualified entries only through their witnessed immutable evidence and current v2 validation rules, not caller-provided JSON. A newly unavailable or rejected sibling cannot disappear by submitting a shorter list. Concurrency locks the source/predecessor; stale writes cannot overwrite another sibling's progress. Failures retain the last recorded full composition plus explicit new unavailable state where witnessed.

Private SQL can reuse `closure_wire_tokens_v1` lexical machinery under a **new** envelope/physical projection that accepts multiple ranges and enforces these bounded counts. Existing closure single-message projection must remain unchanged. SQL derives all ranges/UNH references, BGM functions/document IDs, FR/DO, LI, DTM/UTC and every LIN occurrence from `sources.raw_payload`; compares exact ordered membership with canonical and object facts; validates any accepted marker only inside its range. Bind both source/hash and physical key to actual business association/point/site/owner rows in one MVCC read. Negative forged-index cases must fail even when source hash, point ID, ID spelling and case are unchanged. Caller-selected slice/hash-only proof is insufficient.

Review APIs/UI (`reviewReceivedStructuralSource.ts`, `structure-actions.ts`, `ReceivedStructureReview.tsx`) select checked physical message/object, show UNH ordinal/reference and own document/LI/dates, and cannot approve the source by reviewing only the visible first child. Full-source review can iterate bounded children only with real individual owners. Root lookup must use original assessment+physical scope; current `logicalScope` first-match search is insufficient when the same object occurs twice. Coverage adds baseline physical scope. Replacement pointers add prior physical object scope, not just source UUID/assessment/hash. A replacement may refer to another physical message only through a supported explicit lifecycle, never array ordering alone.

`StructuralVersion`, `StructuralReplacement`, coverage baseline and selected-state provenance must carry the full physical key. Replace `Map(sourceMessageId)`/parent/replaced sets in `structuralSourceSelection.ts` with composite keys; retain source ID/hash as common provenance. Update closure/cancellation reference types as consumers, preserving their already-qualified lifecycle conditions; do not broaden those conditions to make multi-message pass.

`structuralSourceReadset.ts` enumerates every checked message and object. It must distinguish a physically unresolved envelope (global uncertainty) from a known scoped rejected/unavailable sibling (retained scoped blocker). Initial v2 policy requires source-complete before using any of that multi-message source's objects as positive structural inventory; partial operational success alone is insufficient. Known scope can avoid poisoning independent unrelated sources/objects, but the incomplete source is never omitted from inventory. Unknown scope remains global unresolved. Selection still enforces qualified post-ledger roots, replacement chains, dates, closure boundaries and the real processing-time knowledge cutoff; no future witness changes a saved cutoff. UTILTS matching must preserve source physical provenance even though its business comparison key remains exact object+agency+legal parties.

## Necessary tests and native proof

- Two same-function Z04 messages with distinct actual outboundZ03 LI/points, complete live canonical registry decisions, actual successful switch/supply commits, v2 assessment and availability witness; subsequent reviewed Z06/Z10 and UTILTS select the intended physical root. Assert actual selected physical provenance and final matched result, genuine eligible E61/E62 mismatch, and internal-review/no-response/no-quantity result for incomplete evidence. Both callbacks must survive; a later sibling witness must not alter a saved earlier cutoff or finalized quantity. Do not seed accepted switch rows as the only construction evidence.
- Two same-function messages with repeated314=1 and258 restarts; equal object text in two physical scopes stays separate. Distinct subtype/date/party contexts cannot inherit first-message policy. Direct same-sender receiver remains tenant-qualified for each child.
- Second-only bad field, missing rule pack, unknown subtype, wrong party/tenant, failed business write, zeroLIN and budget overflow all remain visible; no universal source approval, no prefix success. First success/second failure retains real first business outcome and idempotent retry; second later recovery appends full composition without replaying first write.
- Wrong UNZ count/reference; incorrect UNT count/ref; duplicateUNH references; nested/missingUNT; mixed functions; orphan segments; released `UNH` text/customUNA; limit+1 for bytes/messages/LIN/segments/facts. Limits yield internal incomplete rather than invented national error.
- Native SQL append forgeries: change only messageIndex/reference or UNH/UNT range; borrow second object's first-message LI/DTM/party/owner; duplicate/drop a physical sibling; shift local/global LIN indices; substitute a same-ID object from anotherUNH. Exact source hash stays fixed: all reject.
- Source/hash/tenant/environment immutability, unauthorized table/RPC calls, stale predecessor writes, concurrent finish/review, business success followed by evidence/witness interruption, earlier-cutoff and later-retry behavior. A copied receipt never becomes a fresh seed.
- Same-object duplicate/correction collision holds until explicit dependency supported. Replacement, coverage baseline and closure references from one physical message cannot attach to its sibling. SourceId-only map regression must be demonstrated with two versions from one source.
- ACK fixture proves exact policy-required envelope/message references, no duplicate response on retry and no missing second response due to source-only key. Owner failures do not change already committed responses. Retain single-message/tenant/register/native regressions.

Extend the actual `inboundProcessing` integration, register-evidence, source-owner session, reviewed-source/readset/selection and source native suites, plus scoped ACK integration. Disposable native SQL replay must exercise source capture→real commit association→append→witness→snapshot, not only helper predicates. No tests were run for this report; counts would not establish full E035 acceptance.

## Engineering versus unavailable past evidence

Envelope views, per-message canonical invocation, scoped business dispatch/associations, callback aggregation, SQL physical binding, ACK isolation and composite selection keys are concrete engineering. The national same-function packaging case requires no invented permission. Old envelopes whose second message was never applied lack an actual business outcome: newly correct parsing cannot manufacture one. Reprocessing may create a genuine current operation/witness with proper dates; it cannot fabricate past availability, pre-ledger completeness, an outbound case or already-missing legal authority. Full E035/masterplan status remains unchanged.
