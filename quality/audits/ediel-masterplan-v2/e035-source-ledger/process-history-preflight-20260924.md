# E035 C-PB-1 outbound and process-history producer preflight

Read-only preparation, 2026-09-24, for Task 3 after the independent sealed-Z05 Task 2. No product/schema/plan edit, tests, commit, hosted operation, market send or delegation. This is a bounded producer contract for the already approved `cancellation-process-basis-design.md` C-PB-1, not positive C authority.

## Actual send topology and gaps

`lib/ediel/prodat/builders/z08.ts` renders Z08 with default H; `businessSemantics.ts` defines Z08:H as supplier rescission request, and `deadlinePolicy.ts` addresses outbound Z08H. I found no dedicated `prepareAndQueueEdielZ08` in `orchestrator.ts` or the listed admin prepare actions. Generic outbound messages/intents may still reach transport; the reader must inspect actual original code/subtype/wire and cannot assume one creation UI enumerates all Z08H. Test/TGT Z08 data is not a production dispatch source.

There are **two** actual send entries. `processEdielOutbox` claims prepared/queued rows and calls `sendOutboxItem`; `orchestrator.sendQueuedEdielMessage` directly calls `sendEdielMessageViaSmtp` and only afterward supersedes open outbox rows. The shared `lib/ediel/transport/index.part-2.ts:318` function constructs normalized EDIFACT and one of several MIME modes before `sendEdielEmail`. It currently inserts a pre-send `ediel_message_payloads` raw snapshot via `storeTransportPayloadSnapshot(...).catch(console.warn)`, so even its presence is neither mandatory nor dispatch evidence. S/MIME EML archiving covers one MIME route, not all Z08H. The canonical outbound `ediel_messages.raw_payload` has an immutable hash after rendering (`20260713100000_ediel_completion_and_platform_contract.sql:690–700`), and `ediel_outbox` copies that hash on message binding, but mutable status/outbox and legacy `outbound_requests` cannot certify provider acceptance.

The worker's atomic `claim_ediel_outbox_items` assigns `current_send_attempt_id`; direct `claim_ediel_outbox_item` does likewise. Sending updates outbox by that attempt ID, but a direct `sendQueuedEdielMessage` has no such outbox claim. The worker checks already sent message status and skips SMTP; this shortcut's `message_sent_at ?? new Date()` is a projection convenience, **not an original dispatch instant**. Generic `createOutboxItem` upserts on lock key and emits a queued event, also not dispatch. `claim_ediel_outbox_items` turns stale `sending` into `delivery_uncertain` and only claims prepared/queued; lock-release requeue only affects blocked, unsent rows. The old `legacyOutboundBridge` explicitly rejects queued/zero-attempt/no-sent as sent evidence.

`sendEdielMessageViaSmtp` calls `sendEdielEmail`, checks accepted/rejected recipient sets, then mutates `ediel_messages` status/time and writes a sent event. An exception after SMTP acceptance becomes `SmtpDeliveryUncertainError`; the worker records `delivery_uncertain` when possible, with an explicit persistence-failed return if that write fails. Socket timeout/closure around DATA is also uncertain (`transport/smtpOutcome.ts`), not a provider rejection. `sendOutboxItem` tracks `providerAccepted` locally; a process crash can lose that boolean. A direct send exception before status persistence can leave `queued` and otherwise be retried. Existing direct-send outbox bridge is after transport and logs reconciliation failure; it cannot protect the pre-status crash window by itself. This is the load-bearing retry seam for Task 3.

## Finite immutable producer contract

Add a private, tenant/environment-scoped append-only **outbound Z08H attempt ledger** with no cascade dependency on mutable `ediel_messages`/outbox, forced RLS, revoked direct DML, service-only wrappers, DB-computed hashes, bounded original bytes, predecessor and separate committed visibility witnesses. Derive eligibility from canonical original PRODAT Z08/H and sealed source fields, not a caller's subtype/status. Save exact outbound sender/receiver (reverse their role when correlating to inbound Z05), physical object/agency, LI, proposed stop, parties, customer/point/supply graph and source operation/intent/outbox IDs where proved. Missing components are wildcard candidate scope, not an unrelated finding. Keep `raw_payload` and the actual normalized EDIFACT bytes/hash distinct; the latter is constructed before transport packaging. Do not infer a legal rescission from a queued original.

At the **shared transport** boundary, after final route/readiness/preflight and normalized payload construction but **before any** mode-specific `sendEdielEmail`, call a DB `begin_z08h_dispatch_attempt` operation. It verifies current sealed original/hash, company/environment/route and a unique **per-original** reservation; uses the outbox `current_send_attempt_id` only after binding it to the actual claimed outbox row, message, company, environment and current worker fence, and generates its own stable attempt ID for direct send. The direct action derives its actor from authenticated server context; the service wrapper and SQL recheck tenant, operation and actor authorization. Route/MIME override or a newly claimed outbox attempt cannot form a new original identity. It records `prepared_original` plus source/attempt visibility. A second entry (direct versus worker, duplicate worker, or retried direct call) sees the reservation and must not send while unresolved **or after accepted/partially accepted evidence**. If preparation capture fails, **do not call SMTP** and report evidence-owner unavailable. A prepared original alone never proves send.

Immediately before entering the provider call, a conditional DB transition from the current reserved owner to `provider_call_entered` must return a **one-time proceed token**, consumed by exactly one invocation. It checks the current worker/direct fence and original; two callers sharing an attempt ID cannot both proceed, and a stale worker resumed after a newer reservation cannot enter. A preparation may be released/replaced only by an authorized operation proving provider-entry was never committed, with fencing that prevents the old paused invocation from later proceeding. After provider-entry a crash may mean accepted or not; automatic retry is forbidden even after outbox lock expiry/status reset. If the mark fails, do not call provider. A crash after mark but before I/O remains uncertain, not falsely sent or safely retryable. Append immutable attempt events/revisions for `prepared_original` → `provider_call_entered` → provider observation → separately witnessed observation or authorized reconciliation; do not overwrite facts. Accepted or partially accepted submission is permanently **no resend for that original**, even if mutable message/outbox stays queued. Status/outbox projections are repairable from the witnessed observation without SMTP. A proven explicit all-recipient rejection may become eligible for a *new fenced attempt* only through separately authorized reconciliation after checking recipient/route and the old terminal negative result; generic automatic retry does not do this.

The shared wrapper around all five `sendEdielEmail` branches records a **post-provider result** before the current `rejected.length>0` failure branch: exact nonempty accepted list, rejected list, SMTP Message-ID/response, server observation time, attempt and original/hash. Nonempty accepted **and** nonempty rejected is `partial_acceptance`, no full resend; a complete returned rejection with zero accepted is distinct from partial acceptance. An explicit SMTP negative response or pre-connect failure is distinguished from successful acceptance and from ambiguous DATA/socket loss. Malformed or empty provider result after provider-entry is uncertain, never proof of non-submission. If even the failed-event append fails, the immutable provider-entry reservation still blocks duplicate send. On DATA timeout/connection ambiguity append uncertain if possible. If post-acceptance DB append fails, throw/return `delivery_uncertain` and keep the pre-provider reservation as the reader's uncertainty signal. Never repeat SMTP just to repair evidence.

Persist **physical encoded payload identity**: canonical `ediel_messages.raw_payload` UTF-8 hash, normalized EDIFACT text's actual transmitted `Buffer.from(normalizedPayload,'latin1')` byte length/hash for EDIFACT (the transport selects `latin1`), and MIME/recipient envelope binding, with MIME mode/encoding. Do not re-hash non-ASCII EDIFACT as UTF-8 and pretend it equals transmitted bytes. Other families use their selected UTF-8 encoding but are outside Z08H. Mode-specific packaging/archiving failure before provider call is a preparation failure if provider-entry has not occurred; if conservatively marked entered, leave an uncertainty hold. Observation time is server observation, not exact unobserved provider acceptance time, delivery or legal validity.

Reconcile the existing mutable message/outbox status and `projectSentEdielSourceState` **after** the immutable accepted observation, without replacing that record. For direct send, the shared reservation must also prevent a later direct/outbox retry if message status/event persistence fails; the current status-based skip alone is insufficient. A source/readset containing `provider_call_entered` without an independently witnessed accepted/rejected result is incomplete for dispatch timing and rescission interpretation. A committed accepted event may be used as an actual technical dispatch observation only with exact original/attempt binding and saved cutoff, not as evidence that the underlying termination was valid. Provider accepted at time T and later business ACK remain separate facts.

## Complete scoped readset and retention

At one saved cutoff/**single database MVCC statement**, read three required universes: (1) potentially matching outbound Z08H original/attempt revisions and actual dispatch observations, including unresolved attempts; (2) sealed received original Z05L/LK, C, possible new Z05, their assessments and witnesses from `gridex_received_sources`; (3) linked customer/contract/termination/rescission transition history. **Scope first, then count before semantic acceptance filtering**: discover all potentially relevant candidates within authenticated tenant/environment and conservative process/object/customer interval, applying only independently immutable identity/link facts to prove unrelatedness. Count scoped candidates (including raw/rejected/unwitnessed/malformed ones) and enforce per-set row/byte limits. A proven unrelated large point cannot overflow this point's readset. Missing fields are wildcard scope; a mutable customer link conflicting with an original point, bad party/date, invalid LI or failed canonical assessment cannot exclude a potentially same-point candidate. Return scoped failure with known scope and unknown dimensions, never a foreign-tenant disclosure. Capture exact source counts, predecessor/witness sets, coverage start/end, first available producer epoch, and missing spans from original supply/process initiation to cutoff. Reader failure, overflow, interrupted producer or an old uninstrumented Z08H send yields **affected-scope** `complete:false`. Only a genuinely unbounded same-context outage broadens the hold. Neither no rows nor count-complete current tables proves no Z08H ever existed. The C-PB-3 raw/unreviewed/rejected/unwitnessed concern and earliest plausible/unknown boundary blocker are independent of provider or semantic eligibility.

| Scope oracle | Required result |
|---|---|
| Same LI, immutably proved different point | Unrelated; no spillover or capacity consumption for selected point. |
| Same point, missing customer or party | Candidate with wildcard component; hold if unresolved, no authority. |
| Point/customer links conflict or original malformed | Cannot exclude solely from mutable link/canonical rejection; scoped unresolved. |
| Semantically rejected same-point Z08 context | Still in universe/blocker; never positive dispatch/process authority. |
| Proven unrelated point with its own overflow/retention gap | Does not globally hold this point. |

Actual linked contract producer `lib/customer-contracts/db.ts:addCustomerContractEvent` invokes `gridex_record_customer_contract_event_v1`, which atomically writes a typed `customer_contract_events` row, `domain_events` and permitted contract status effects (`20260727165000_quote_and_customer_contract_event_integrity.sql`). The move-out/termination customer action (`profile-actions.part-1.ts`) writes `termination_reason:'move_out'` events; customer decision action in `profile-actions.part-2.ts` writes withdrawal/cancelled reasons. These are useful **process candidates**, not independent authenticated correction cause. Customer archival in `profile-actions.part-2.ts` calls `deleteByColumn('customer_contract_events',...)` and `deleteByCustomerId`, so current event row counts cannot establish long-term coverage. Other customer/contract/case rows are mutable. Capture at the actual DB command or table transition trigger in the *same transaction*, rather than a best-effort later callback; record event/row ID/type, tenant, actor/source, old/new graph/status, DB record time and separate committed witness. A relevant mutation must atomically append its observation, leave a durable scoped gap, or be rejected. Do not backfill missing pre-producer events from latest status. A process that started before every required producer epoch remains incomplete until authentic retained history is independently reconciled.

## Exact tests and implementation boundary

Native sequence must cover prepared-but-never-provider-call, safe release before provider-entry plus stale paused caller, failed preparation (zero provider invocations), accepted SMTP+post-capture, **accepted with rejected recipients**, all-recipient explicit rejection under authorized reconciliation, malformed/empty provider result, pre-connect failure, DATA timeout, crash after `provider_call_entered`, accepted SMTP followed by ledger/status/event/outbox projection failure, accepted evidence with mutable queued projection, duplicate same-attempt entry, stale worker claim, direct-versus-worker race and route/MIME change. Count actual `sendEdielEmail` calls; same original must never cause a second send after accepted/partial/uncertain state. Check physical latin1 bytes/hash versus UTF-8 text hash on non-ASCII EDIFACT, recipient envelope binding and all five branches. An accepted provider result does not become delivered/ACK or positive correction. Old queued is not sent, and old sent lacking immutable producer coverage is `complete:false` rather than retroactively approved.

For process snapshot: a synthetic relevant Z08H with valid original but uncertain delivery holds; authentic accepted conflicting Z08H still holds pending rescission interpretation; a proved unrelated Z08H leaves another point unaffected. Wrong tenant, reversed FR/DO failure, same LI on another point, missing object/date/party, reader overflow, deleted customer event, source/assessment revision after cutoff, and missing inception span all exercise scoped incomplete decisions. Native concurrency probes must commit capture on either side of saved cutoff and show no snapshot sees a published event without its availability barrier. Old saved receipts/finalized retries remain byte-identical.

**Remaining factual gaps:** shared transport has no stable direct-send attempt key or durable all-branch reservation today; implementation must add and native-qualify it. No dedicated production Z08H prepare action was located; the generic send guard covers any actual Z08/H original, while missing creation remains a separate F5 capability question. The third-set table-trigger map still needs exact-head schema/type and direct/RPC/batch/archive native inventory before it can ever claim `complete:true`; it is intentionally partial until then. Historical outbound sends, deleted customer events and pre-producer spans cannot be inferred from mutable rows. These are engineering/coverage gaps, not a generic legal-permission request or an assertion of historical absence.
