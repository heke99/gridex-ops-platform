The old `upsert(row,{onConflict:'lock_key'})` would replace the `status` of an existing `sending`, `sent`, `delivery_uncertain` or `superseded` row even if a message status lagged the transport worker. The direct helper test first failed 4/5 on those transitions. A separate test forced a worker transition between lookup and conditional retry: the first candidate returned stale `failed`; the reread now returns `sent` without a queued event. The source-valid Z04 consumer remains unchanged. Native SQL uses the real `ediel_outbox` lock index and guarded status update in a disposable transaction. No schema or generated type changed; the generic outbox helper is used by three consumers and must receive ordinary full CI.
