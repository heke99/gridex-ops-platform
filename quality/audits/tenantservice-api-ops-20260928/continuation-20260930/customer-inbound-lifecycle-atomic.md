Ordinary legacy raw receive INSERTs remain possible under their existing policies but do not create this new trusted evidence. The command requires that exact fresh service capture on every call/replay. Existing PRODAT append-only original-source capture remains an additional owner; its older general authenticated capture boundary is not repaired or presented as globally trusted by this packet. No historical ACK/Z04 capture or backfill occurs. Actual bounded release-aware lexical parsing checks envelope references/counts and protocol fields; Z04 binds the exact originating Z03 LI/facility/full transport parties and unique FR/DO legal party tuples. ACK acceptance/rejection comes from exact UCI/ACW/ERC wire facts, not mutable parsed payload. An accepted business reply requires the actual originating Z03's nonnull send timestamp, exact immutable payload hash and append-only dispatch witness. The witness captures only a newly observed null-to-nonnull sent-time UPDATE under PostgreSQL's installed `service_role`, with canonical rule pack/route/profile/source-operation and exact switch graph. It never captures a sent INSERT, historical backfill, or a no-op projection of an already sent row. The role guard subsequently rejects an ordinary authorized tenant writer's first-sent UPDATE atomically, including when request claims say service role; it does not infer transport dispatch solely from caller-supplied status. Trusted service remains the server boundary, and the core's service UPDATE is explicitly simulated rather than a provider receipt. Mutable switch submitted/prepared/queued state cannot authorize an unsent source. Genuine prepared/queued switch rows are allowed only with the service-captured sent source witness, because the existing sender does not itself advance those switch rows.

Fresh source status `failed` is denied. A source projected to `acknowledged` is eligible only with an exact earlier positive final ACK receipt from this owner bound to the same origin/hash/send time. Negative ACK replay may preserve its own failed source under its exact existing receipt; this gives no fresh terminal-state permission. There is no historical witness fabrication or terminal state broadening.

Every fresh command and permanent replay rebinds current company/customer/site/point/contract aliases, active grid owner, origin resource/party fields, exact workflow/application and current operation ownership before a receipt can return. Ambiguous periods/workflows are held. Point FOR UPDATE serializes this command's same-point overlapping period checks; future intervals and existing pending confirmations are checked, not only intervals containing the new start date. This is bounded owner serialization, not a global exclusion constraint or executed multi-session different-switch concurrency receipt.

Private receive/dispatch witnesses and receipts are append-only with FORCE RLS, fixed search paths and no PUBLIC/anon/authenticated invocation or evidence-manufacturing privileges. Service can read captured witnesses, cannot insert them, and can insert/read permanent command receipts under this service-owned transaction. The existing lexical function's ACL remains unchanged behind a narrow lexical facade. No provider, certificate issuance, template delivery or activation is performed in the business transaction.
