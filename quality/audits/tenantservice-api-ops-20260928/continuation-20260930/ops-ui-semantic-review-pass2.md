## Confirmed findings handed to owners, and source candidates

1. **Billing import false failure and unchecked persistence (owner: billing worker/root).** Before correction `done('success', ...)` ran inside try, and its Next redirect throw entered catch, which called done('error', error.message). Row insert/final batch update errors were ignored. Actual exported-function RED/GREEN qualification is assigned to the billing worker; this report does not pre-claim its eventual result. Page read vs action write controls also need explicit readonly projection. Frozen source family `OPS-FAMILY-8fdd036fe711e74a` had no test references.
2. **Contract permission helper ignores authoritative platform flag (candidate handed to root).** `lib/admin/guards.ts` F7 uses canonical `isPlatformAdmin` authority; `lib/contracts/permissions.ts` isContractSuperAdmin checks only platform-looking role names and bypasses explicit contract permission checks. A company-scoped platform-named role must be regression-tested at this application boundary and canonical SQL before any exploit/data-effect claim. No code changed here.
3. **Market source connection label exceeds observed effect (candidate).** The current test action queries stored spot-price observations and writes metadata; button says Testa anslutning and successful badge says Anslutning verifierad. No provider call appears in this action. Test meaningful local-data result wording, policy-row creation/zero-row failure and persisted status before changing behavior. Page/action pricing permissions are aligned; no false readonly defect is asserted.
4. **Integration controls/outcomes (candidate).** Billing read page renders test/reprocess controls whose actions require export/pricing.write, has no explicit readonly projection, and status-save error is ignored. Real external Ping/reprocess must remain fail-closed/synthetic for qualification. Provider-related internals do not accept the actual UI/action operation.
5. **Bulk candidate scope and webhook zero-row effects (unproven boundary).** Some authenticated-client bulk reads rely on RLS without explicit selected-company equality; webhook updates have explicit company/id predicates but do not verify matched rows. These observations need real SQL/actor/resource postcheck. They are not labeled confirmed cross-tenant leaks or accepted effects.
