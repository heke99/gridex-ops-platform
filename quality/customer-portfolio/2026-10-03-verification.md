## System-wide consistency pass

| Finding | Fix |
| --- | --- |
| Monthly builder wrote new/ended/active customers from `customers.created_at` / `ended_at` / `status`, then the snapshot overwrote them (two definitions, brief inconsistent window) | Builder no longer writes these; the atomic snapshot owns them |
| `lib/analytics/db.ts` live fallback used `created_at` / `ended_at` | Uses `getPortfolioMonthForCompany` (same RPC) |
| Company detail page: "new" = `created_at`, "closed" = `updated_at` + status | Uses `getPortfolioMonthForCompany` |
| White-label owner/admin could run Ediel actor-testing writes (incl. production activation) on every tenant of the platform | Writes require platform admin or admin membership in that company; white-label stays read-only |

Deliberately unchanged: the dashboard "Aktiva kunder" (`customers.status = 'active'`) counts
customer records, not supplied customers; contract/lifecycle code keeps that status in sync.

## Performance pass (20261003150000_portfolio_analytics_rollups_performance.sql)

Seed: `scripts/sql/customer-portfolio/30_perf_seed.sql` — 1 company, 5 000 customers and supply
periods, 1 000 points with hourly values for 12 months (8.76M rows), 10 000 requests, 5 000 POAs.
Local PG16, warm second run, `service_role`.

run rebuilds (`40_rollups.sql`).
