# Legacy staff role-reference compatibility — 2026-10-04

Base: final main `8f3b42f112fadb38b6c12896883cec0403ebcd8d`.
Isolated branch: `codex/staff-role-id-nullability-fix`.

Confirmed blocker: production retained `public.user_roles.role_id uuid NOT NULL`
without a default, while the qualified clean schema has a nullable UUID. Historical
`CREATE TABLE IF NOT EXISTS` and `ADD COLUMN IF NOT EXISTS` never normalize the
old constraint. The unchanged captured canonical staff core inserts role text
without `role_id`; its mapped wrapper fills the reference later in the transaction.
Consequently real role-change and enable commands fail with SQLSTATE `23502`.

The independent rollout reviewer supplied catalog evidence: eight existing rows
all have non-null role references; the validated role FK uses `ON DELETE CASCADE`,
the company FK uses `ON DELETE SET NULL`, RLS is enabled, and effective authenticated
table/column INSERT/UPDATE/DELETE privileges are absent. This repair did not read
private synthetic state or call a hosted database.

Forward `20261004165620_staff_user_role_id_nullability.sql` was generated by
the installed Supabase CLI `2.101.0` using `migration new`. Its SHA-256 is
`efdc9d67fcb6e3edd6d77e97de0b5c79978a2b3673d6bad1607880b5cbe98510`.
It requires the existing ordinary UUID column and changes only its nullability.
The transaction has a 10-second lock timeout and a 120-second statement timeout.
Already-nullable replay is idempotent; incompatible/missing columns abort before
alteration. Rows, references, defaults, indexes, functions, triggers, RLS and grants
are unchanged. No backfill is required. Any failed apply or preflight rehearsal
rolls back atomically; no nullable rows are populated by this migration.

`__tests__/staff-user-role-id-nullability.test.ts` uses the actual captured
canonical/staff permission, access, scope, hash and last-administrator function
bodies without edits. Finite supporting tables reproduce only the evidenced
legacy nullability/FK state; they are not an authentic full PostgreSQL replay.

- Both real guarded role/enable chains reproduce `23502`, retaining rows and
  command/audit state after the failed transaction.
- The exact forward permits successful role changes and disable/enable, final
  mapped non-null references, durable actor/client audit, and authorized replay.
- Eight seeded legacy rows and complete table constraints/indexes/policies/
  triggers/ACL metadata survive repeated application. Transaction rollback
  restores the original column constraint.
- Invalid non-null role references still fail the FK; tenant-bound platform roles
  with null `role_id` still fail the actual scope guard; authenticated direct
  writes, insufficient client scope, revoked-client replay and last-admin demotion
  remain rejected. Missing/wrong-type columns fail closed.

The existing mandatory `scripts/staff-user-commands-regression.sql` now requires
the nullable UUID column and unchanged RLS/effective authenticated write ACL,

tenant-bound platform role with a null reference. Its invitation embedded harness
adds captured scope functions/triggers and matching role-table RLS/ACL so the
