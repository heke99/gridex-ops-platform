# BUG-004: API client public reference reversibly exposes its UUID

## Summary

The lib/integrations/tenantContext.ts:224-250 code path violates REQ-007: api_client_reference is client_ plus client.id with hyphens removed. In practice, Call integration/context for a client whose internal ID is a known UUID.

## Spec reference

- Requirement: REQ-007
- Spec basis: ../../upload/Pasted markdown(20260810-093430).md:86; quality/REQUIREMENTS.md (REQ mapping)
- Behavioral contract quote: “Gör api_client_reference faktiskt opaque.”

## The code

At lib/integrations/tenantContext.ts:224-250, the current implementation does not enforce the required boundary. api_client_reference is client_ plus client.id with hyphens removed. The contract instead requires: Use a persisted random or tenant-bound cryptographic reference that cannot reconstruct the primary key.

## Observable consequence

Trigger: Call integration/context for a client whose internal ID is a known UUID. The observable result is that api_client_reference is client_ plus client.id with hyphens removed. The expected outcome is: Use a persisted random or tenant-bound cryptographic reference that cannot reconstruct the primary key.

## The fix

The proposed change moves enforcement into the shared boundary named by the requirement so parallel routes cannot silently diverge.

```diff
diff --git a/lib/integrations/tenantContext.ts b/lib/integrations/tenantContext.ts
--- a/lib/integrations/tenantContext.ts
++ b/lib/integrations/tenantContext.ts
@@ loadExternalTenantContext
-    api_client_reference: `client_${client.id.replaceAll('-', '')}`,

```
